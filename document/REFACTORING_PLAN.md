# 主站重构执行计划

## 执行规则

- 按编号顺序执行，每项完成后保持项目可运行、可验证、可回滚。
- 每个编号至少形成一个独立提交，不跨计划混合。
- 大型任务按“测试、机械重构、行为修改、数据迁移”拆分提交。
- 文件移动和业务行为变化不得放在同一提交。
- 提交信息使用 Conventional Commit 前缀和中文主题。
- `.env`、本地数据库、日志、备份和生成构建产物不进入 Git。
- “小抄儿”始终排除，仅验证接口兼容。

## 阶段一：交接与测试基线

### R00 固化交接基线

- 记录目标架构、范围、外部接口和数据迁移契约。
- 保护当前领先提交和用户未提交文件。
- 记录现有依赖、迁移、URL、部署和验证结果。

### R01 核心行为测试

- 分享创建、编辑、删除、搜索和详情。
- 匿名分享、用户资料、合集、点赞收藏和计数。
- 审核、举报、站内信和公告。
- 所有可见性、审核状态和用户身份组合。
- 小抄儿依赖的两个 API 契约测试。

### R02 统一验证与 CI

- Django check、迁移检查、完整测试和依赖检查。
- 前端 lint、TypeScript 检查和隔离构建。
- SQLite 与 PostgreSQL 测试矩阵。

## 阶段二：安全与一致性

### R03 生产配置安全化

- 开发、测试和生产设置分离。
- 密钥、主机、HTTPS、代理头和安全 Cookie 强制校验。

### R04 富文本安全

- 用 Quill 2 替换 CKEditor 4。
- 服务端 nh3 白名单清洗。
- 消除用户内容进入 `innerHTML` 的路径。

### R05 输入和防刷边界

- 分享码规范化、格式和长度校验。
- 标题、描述、举报和搜索输入上限。
- 注册、登录、匿名创建、举报和计数频率限制。

### R06 权限策略统一

- 建立集中式内容访问策略。
- 详情、搜索、合集、API、点赞、收藏、复制和举报共用同一规则。

### R07 HTTP 与事务

- 所有状态变化改为 POST 并检查 CSRF。
- 修复开放重定向。
- 审核、举报、日志和站内信使用原子事务与幂等处理。

## 阶段三：依赖、模型和后端架构

### R08 Django 5.2 与依赖整理

- 先升级 Django 4.2 最终补丁，再升级 Django 5.2 LTS。
- 固定直接依赖和开发依赖，移除无用依赖。

### R09 数据模型与迁移工具

- 添加索引、唯一约束和状态一致性约束。
- 实现版本化导出、导入、校验和隔离报告。
- 配置 SQLite 并发和备份策略，保持 PostgreSQL 兼容。

### R10 拆分后端分层

- 引入 policies、forms、services、selectors 和 presentation。
- 按分享、账户、合集、审核举报、消息和 API 拆分视图。
- 收敛所有状态变化入口。

### R11 API 与 HTMX 片段

- 保持公开 API 契约。
- 为主站局部交互增加稳定的 HTML fragment 响应。
- 正确处理缓存、`Vary: HX-Request` 和错误状态。

## 阶段四：前端架构和 UI

### R12 主站 Vite 管线

- 建立 TypeScript、HTMX、Alpine 和 CSS 构建入口。
- 移除主站全局 Vue、重复脚本和内联逻辑。

### R13 设计系统

- 建立颜色、排版、间距、圆角、阴影和响应式令牌。
- 建立表单、按钮、卡片、标签、通知、模态框、分页、空状态和骨架屏组件。

### R14 全局框架与浏览页面

- 重构导航、搜索、用户菜单、消息入口和页脚。
- 重构首页、瀑布流、搜索、用户主页和合集。

### R15 分享与用户工作流

- 重构分享创建、编辑、详情、复制、二维码和分享图。
- 重构认证、个人资料、我的内容和站内信。

### R16 管理页面与可访问性

- 重构公告、审核和举报页面。
- 完成桌面、平板、手机、键盘、焦点、对比度和视觉回归测试。

## 阶段五：Windows 部署与发布

### R17 性能与可观测性

- 建立查询数量和关键请求性能基线。
- 清理 N+1 查询，增加结构化日志和健康检查。

### R18 Windows 生产服务

- Waitress 监听回环地址。
- WinSW 管理服务生命周期、自动恢复和日志轮转。
- 现有 Nginx 保持兼容入口并纳入配置备份。

状态：仓库侧实现和自动化验证已完成；目标机安装、真实 Nginx 配置核对与正式启用仍属于 R20，不能视为已经上线。

### R19 数据迁移演练

- 使用线上数据库只读副本执行完整导出、导入、校验和恢复。
- 未取得生产副本前不得进入正式切换。

状态：仓库侧工具和合成数据的完整 Proposal → Review → Approval → 双次离线 E2E 已完成；正式线上不可变数据库与媒体副本尚未取得并完成双次演练，因此 R19 仍未完成。操作步骤和证据门禁见 `PRODUCTION_COPY_REHEARSAL.md`。

### R20 正式切换与发布验收

- 短维护窗口冻结写入。
- 最终备份、迁移、校验、冒烟和切换。
- 正式切换前必须使用 `python manage.py changepassword <线上管理员用户名>` 交互轮换线上管理员密码，并验证新密码可以登录、旧密码已经失效。
- 密码轮换验证记录必须包含执行时间、操作者、账户标识和验证结果，但不得记录新旧密码；记录缺失时禁止正式切换。
- 保留旧库和旧版本回滚路径。
- 更新开发、部署、备份和故障恢复文档。

## 提交边界

示例提交：

- `docs: 确定主站重构目标架构`
- `test: 补充分享访问权限矩阵测试`
- `fix: 清理用户富文本并消除存储型XSS`
- `refactor: 拆分分享查询与领域服务`
- `feat: 建立主站设计令牌和基础组件`
- `ops: 使用Waitress和WinSW托管主站`

任何提交在产生时都必须通过当时已有的完整验证。
