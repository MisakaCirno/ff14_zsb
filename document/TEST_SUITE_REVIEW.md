# 测试套件审查

审查基线：2026-07-24。

## 结论

测试数量本身不是主要耗时来源。原有 630 项测试中，大量项目是无需数据库的配置、模板和前端接线检查；主要耗时集中在历史迁移、数据可移植，以及测试用户反复执行生产级密码哈希。

本次没有为了降低数字删除独立的数据安全、权限或业务场景。已完成以下调整：

- 合并点赞／收藏的三组对称重复测试，以及一组完全相同的配置检查。
- 完整套件由 630 项变为 626 项，已不存在 AST 方法体完全重复的测试。
- 将 51 项数据可移植测试和 33 项历史迁移测试标记为 `slow`。
- Fast 档位运行 542 项快速测试；Full 和 Release 仍运行全部 626 项。
- `APP_ENV=test` 使用快速密码哈希器；生产环境继续使用 Django 的安全默认值。
- 删除 GitHub Actions；所有验证在本机或目标服务器完成。

## 当前构成

| 类型 | 数量 | 用途 |
|---|---:|---|
| `SimpleTestCase` | 151 | 配置、安全头、模板接线、静态前端契约；不创建测试数据库 |
| `TestCase` | 426 | 权限、审核、账户、分享、站内信和页面工作流 |
| `TransactionTestCase` | 49 | 并发、数据库锁、历史迁移和事务边界 |
| 合计 | 626 | Full／Release 完整测试范围 |

慢速组共 84 项：

- 51 项数据导出、导入、格式兼容、序列和恢复测试。
- 33 项历史迁移、逆向迁移和 SQLite 序列高水位测试。

这些测试直接保护用户数据和线上数据库升级能力，必须保留，但没有必要在每次小改动后重复运行。

## 执行策略

日常修改：

```powershell
.\verify.ps1
```

Fast 会跳过 `slow`，但仍执行系统检查、迁移漂移检查、依赖检查、基础运维合约、前端测试／构建和 542 项快速 Django 测试。

合并、迁移或部署前：

```powershell
.\verify.ps1 -Profile Full
```

Full 会额外执行生产副本工具合约和全部 626 项 Django 测试。涉及数据模型、迁移、导入导出、备份或恢复逻辑的修改，不得只运行 Fast。

真实离线端到端迁移和浏览器回归使用：

```powershell
.\verify.ps1 -Profile Release
```

## 保留判断

- 前端源码契约数量较多但成本很低，用于保护 Django 模板与 TypeScript 模块之间的 `data-*`、HTMX、ARIA 和共享组件接口；它们不等同于 Vitest 的运行时行为测试，因此保留。
- 正反向迁移和序列高水位测试看起来相似，但保护方向不同，任一方向失败都可能造成线上数据或自增序列回退，因此保留。
- 数据格式 v1-v5 的兼容测试存在相似断言，但分别冻结不同历史协议；合并会弱化旧数据兼容证据，因此保留。
- PostgreSQL 专属测试在 SQLite 本机环境会跳过，但保留为未来数据库迁移的边界契约，不纳入日常耗时。
